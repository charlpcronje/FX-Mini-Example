# FX Mini Plus — enhancement analysis & API reference

**What this is:** a drop-in extension layer for fx-mini that (a) completes the everyday jQuery API your team already knows, (b) adds jQuery-style effects, and (c) fuses `$` and `$$` into something neither jQuery nor fx-mini had — computed nodes, keyed reactive list rendering, one-call form binding, persistence, and undo/redo. **Everything stays synchronous** — no `await` anywhere in the public API.

```js
import "./fx/fx-mini-plus.js";   // instead of "./fx/fx-mini.js" — that's the whole migration
```

`fx-mini.ts` is generated by `build-fx-mini.mjs`, so nothing here touches it: the layer decorates the `$` results fx-mini produces at call time. When you want it inside the single file later, each module maps cleanly onto a `fx::plus-*` region for the assembler.

Files: `fx/fx-mini-plus.js` (entry) + `fx/plus/*.js` (24 modules, each < 300 lines, OOP, one shared logger). Demo: `plus.html` + `app-plus.js` + `snippets.html` + `components.html`. Tests: `tests/test-plus.html` + `tests/run.mjs` — **74/74 passing in headless Chromium**.

---

## 1. Review notes on fx-mini as it stands

The core design is strong: the value-bag node graph, the sync `@`-loader with suspend/replay, `.as()` grafting, and reactive-bind-by-passing-the-node are a coherent, teachable model. The gaps that show up the moment a jQuery team writes real app code:

1. **API surface.** `$` covers ~25 methods; day-to-day jQuery code leans on ~80 (insertion around elements, set filtering, dimensions, `.data`, `serialize`, effects, `$.ajax`, `$.extend`…). Every gap sends people back to `el.raw()` and vanilla DOM.
2. **Event teardown.** `.off(evt)` without a handler was a no-op, and delegated handlers could never be removed (the wrapper function was anonymous). No namespaces, no `.one()`.
3. **Watcher leaks.** Every reactive bind (`.text(node)`, `applyReactive`) watches forever; replacing content via `.html()` or removing elements leaves dead watchers on the node. Fine for a playground, compounding in an app.
4. **Group ergonomics.** Getters on a Group returned the Group (e.g. `group.text()` discarded the values) instead of the first element's value like jQuery.
5. **Watcher callback trap.** `node.watch((nv) => …)` receives the internal value *bag*, not the value — everyone must remember to call `.get()` inside. (The plus layer always re-reads; worth fixing in the kernel eventually.)
6. **Dynamic content isn't hydrated.** `$${…}` templating only ran at load; markup inserted later needed a manual `$hydrate(el)` that nobody remembers.

The plus layer addresses 1–4 and 6 outright and works around 5 internally.

## 2. jQuery parity — what was missing, now covered

**Creation & ready:** `$("<li>…</li>")` detached element creation · `$(fn)` DOM-ready.

**Manipulation:** `prepend` · `before` · `after` · `appendTo` · `prependTo` · `insertBefore` · `insertAfter` · `remove([sel])` · `detach` · `empty` · `clone` · `replaceWith` · `wrap` · `wrapInner` · `unwrap` — all removal paths dispose tracked watchers; all insertion paths hydrate `$${…}` / `{…}` / `<import>` in the new markup.

**Attributes / properties / data:** `prop` (reactive-capable) · `removeAttr` · `removeProp` · `.data()/.removeData()` with jQuery's dataset coercion ("42" → 42, "true" → true, JSON strings → objects).

**Traversal & set filtering:** `parents` · `parentsUntil` · `siblings` · `nextAll` · `prevAll` · `nextUntil` · `prevUntil` · `filter` · `not` · `has` · `is` · `add` · `eq` · `first` · `last` · `slice` · `map` · `get` · `toArray` · `index` · `even` · `odd` · `each` (also on single handles). FX conventions kept: no match → `null`, one → Handle, many → Group.

**Events:** `on`/`off` rebuilt on a real registry — `.off("click")`, `.off()`, removal of **delegated** handlers, and **namespaces** (`.on("click.menu")`, `.off(".menu")`, namespaced `.trigger`) all work · `one` · `hover` · shortcut methods (`.click(fn)` / `.click()` native-trigger, `focus`, `blur`, `change`, `submit`, `keydown`, …).

**Dimensions:** `width`/`height` (content-box math, box-sizing aware, reactive setters) · `innerWidth/Height` · `outerWidth/Height(includeMargin)` · `offset` (get/set) · `position` · `scrollTop`/`scrollLeft` · `rect()` bonus · `$(window).width()`, `$(document).height()`, window scrolling.

**Effects (WAAPI under the hood, sync chainable API, per-element queue):** `show`/`hide`/`toggle` (instant or animated) · `fadeIn`/`fadeOut`/`fadeToggle`/`fadeTo` · `slideDown`/`slideUp`/`slideToggle` · `animate` (incl. `"+=80"` relatives **and** `scrollTop`/`scrollLeft` tweens) · `stop(clearQueue, jumpToEnd)` · `finish` · `delay`. Honors `prefers-reduced-motion`. Pre-animation inline styles are restored exactly.

**HTTP — node-first, the FX grammar (select the binding, act on it). The verb argument IS the payload:**

```js
const users = $$("app.users@/api/users").get();   // parsed body returned AND grafted onto app.users
$$("app.saved@/api/save").post({ name: "Ada" });  // payload, not config
$$("app.users@/api/users").get({ active: 1 });    // GET payload → ?active=1
$("#panel").load("/page.html #fragment");         // fetch → filter → inject → hydrate
```

Config never rides the payload. It lives in three places, by scope:

```js
$.ajaxSetup({ schema: { template: "envelope" }, headers: { "X-App": "fx" } });  // app-wide
$$("app.pic@/api/pic").options({ dataType: "blob" }).get();                     // per binding (cached, persists)
$$("@/api/x").get(null, { schema: { pick: { ok: "ok", title: "data.title" } } }); // one-shot second arg
```

**Response templates** decide the shape of what verbs return and what nodes receive — declared (and changeable) in `$.ajaxSetup`, exactly where jQuery put its defaults:

```js
$.ajaxSetup({
  templates: { api: (env) => ({ ok: env.ok, body: env.data, code: env.status }) },
  schema: { template: "api" },      // "data" (default: body only) | "envelope" | any registered name
});
// per call/binding: { template: "…" } | { map: env => … } | { pick: { out: "envelope.path" } }
```

This upgrades fx-mini's own `path@url` bindings in place (`fx/plus/api.js` routes HTTP specs through `FxAjax`; module and text `@`-loads still go to the kernel untouched). With the default `data` template the node receives the body on success and `{ error, status }` on failure; other templates apply their shape uniformly to return values and node fan-out. `dataType` covers html/text/json/auto plus `blob`/`arrayBuffer` on the fetch path — status is never silently swallowed.

**jQuery-compat shims** (kept for muscle memory during migration — same engine, same templates underneath): `$.ajax({ url, success, error, complete })`, `$.get`, `$.post`, `$.getJSON`, `$.http` (the raw envelope), `$.ajaxSetup({ suspend: false })` for a global blocking opt-out.

**How it stays synchronous without freezing the page:** the plus layer uses the kernel's own `FXSuspend`/replay machinery. Every plus callback boundary — event handlers (`FxEvents`), `$(fn)` ready, effect-completion callbacks, `$computed` derivations — runs through `FxReplay.invoke` (the twin of the kernel's `invokeWithSuspendReplay`). Inside a boundary, `$.ajax` starts a background `fetch`, throws `FXSuspend`, and the handler **replays** when the response lands — the UI thread is never held. A request memo (keyed `method+url+body`, kept alive until the last suspended operation completes, mirroring the kernel's `httpMemo`) makes replays idempotent: **GETs and POSTs fire exactly once**, verified by test. Outside a boundary (top level, console, third-party callbacks) it falls back to blocking sync XHR so the contract still holds. Opt out per call with `{ suspend: false }`.

**Replay transactions (`fx/plus/tx.js`) — the `counter++` problem, solved with zero ceremony.** Replay re-runs the code before the suspend, which would double every read-modify-write:

```js
$$("app.count").set($$("app.count").get() + 1);   // would run twice…
const d = $$("app.data@/api").get();              // …because of the replay
```

Every replay boundary is therefore a **transaction** — automatically, with no API to remember. All fx graph writes funnel through `fx.set`/`fx.valStore`, so `FxTx` hooks them once and keeps a per-operation *inverse journal* (first touch records the node's prior value bag by reference — exact and free, since the kernel replaces bags on every write). When the op resumes for a retry, the previous attempt's writes are **rolled back newest-first** and the code re-runs from clean state: graph counters, `$list.push`, form writes — all land exactly once, and replays *read* the same pre-state the first attempt read, so locals derive identically. The timing makes it invisible: writes stay visible **during** the wait (your "loading…" renders), and rollback + re-run share one microtask at resume, before the browser paints. Concurrent writes from other handlers during the suspend are detected by reference-inequality and win over the rollback (the replay then re-derives on top). Toggle with `$fxp.tx.enabled`.

For everything the journal can't see, no primitive is needed — just the two natural rules of the model:

1. **State lives in the graph.** That's FX anyway — a counter that matters is `$$("app.counter")`, and then exactly-once is automatic.
2. **Fire-and-forget effects go after the request.** Code after the last suspending call only executes on the completing pass, so `analytics.send()` placed after the `$.get` runs exactly once by construction — verified by test.

The only residual habits: `ev.preventDefault()` before the first server call, and prefer graph-driven rendering (`bindEach`) over direct `.append()` in suspending handlers. A bonus of the wrapped boundaries: a kernel `@`-load that suspends inside one of your handlers now replays cleanly too.

**Utilities:** `$.each` · `$.map` · `$.grep` · `$.inArray` · `$.merge` · `$.extend` (deep) · `$.param` (nested brackets) · `$.isPlainObject` · `$.isEmptyObject` · `$.type` · `$.trim` · `$.now` · `$.noop` · `$.contains` · `$.uniqueSort` · `$.parseHTML` · `$.parseJSON` · `$.escapeSelector`.

**Plugin bridge:** `$.fn.myPlugin = function (opts) { … }` — registers on every handle *and* group, exactly like old times, and the plugin body can use the reactive methods.

Group semantics now match jQuery: getters return the **first** element's value; setters fan out and chain; traversal collects + de-dupes in document order.

## 3. The reactive superpowers (the new stuff)

### `$computed` — derived nodes

```js
$computed("cart.total", ["cart.items", "cart.vatRate"],
  (items, rate) => items.reduce((s, i) => s + i.price, 0) * (1 + rate));

$("#total").text($$("cart.total"), (v) => `R${v.toFixed(2)}`);   // bind + format
```

A computed node *is* a node — bind it, watch it, persist it. Loop-guarded (`Object.is` + JSON compare), errors contained.

### `.bindEach` + `$list` — reactive lists with keyed diffing

```js
$("#todos").bindEach("app.todos", {
  render: (t) => `<li class="todo" data-id="${t.id}">${t.text}</li>`,
  key:    (t) => t.id,                 // unchanged items keep their DOM nodes
  empty:  `<li class="muted">Nothing yet</li>`,
});

$list("app.todos").push({ id: 1, text: "hi" });      // set-through mutators:
$list("app.todos").update(0, { done: true });        // push / insert / removeAt /
$list("app.todos").removeWhere((t) => t.done);       // removeWhere / updateWhere /
$list("app.todos").move(0, 2);                       // move / clear / set / get
```

Rendered items hydrate (`$${…}` works inside templates), delegated events survive every re-render, and replaced rows dispose their watcher subtrees.

### `.bindForm` — a whole form in one line

```js
$("#checkout").bindForm("app.checkout");   // every named control ↔ $$("app.checkout.<name>")
```

Checkboxes → booleans, radio groups → one value, multi-selects → arrays, numbers → numbers. Reentry-guarded both directions. `serialize()`/`values()` read the same controls.

### `$(selector, context)` — snippet libraries

The second argument of `$` is *where to select*. An FX **node** keeps its two-way-bind meaning; everything else is a context:

```js
const snippets = $$("@/snippets.html");           // one sync load — the @-loader caches by URL
$("#user-card", snippets).removeAttr("id").appendTo("#list");   // stamp a copy
$("section", $("#outer", snippets));              // select inside a stamp
$(".item", "#sidebar");                           // context selector → scoped live query
$("#row", $$("@/snippets"));                      // api binding context → fetched html, cached
```

HTML-string contexts parse once into a cached inert `<template>` (never touching the live DOM) and **selections come back as clones** — the same snippet stamps any number of times, each copy independent. Live contexts (elements, handles, groups, selector strings) don't clone, jQuery-style. Stamped markup hydrates on insert, so `$${…}` inside snippets stays reactive. One file becomes a whole component library with zero build step.

### `fxc` — components on the graph

Real web components whose **props are sub-nodes**. Declare in plain HTML (one library file, many components), register with one sync call, use anywhere:

```html
<!-- components.html -->
<fxc:badge title="${prop:label|new}" as="span">
  <b>${prop:label|new}</b>
  <slot name="heading"></slot>
  <slot></slot>
  <style shadow="false" src="/badge.css">
    this:b { color: $${"theme.accent" | "#2dd4bf"}; }   /* scoped WITHOUT shadow DOM */
  </style>
  <script src="/fxc/badge.js">   <!-- or inline; loaded by the sync module loader -->
    export default class extends fxc {
      label = "new";                       // fields = prop defaults
      mount() {}  unmount() {}  propChange(name, value) {}
    }
  </script>
</fxc:badge>
```

```js
$fxc.load("/components.html");   // register (inline <fxc:*> in the page auto-register at boot)
```

```html
<fxc-badge $label="beta" $node="badge.hero" class="big">…light children fill slots…</fxc-badge>
```

`$attr` seeds a prop; plain attributes stay attributes. Instances live at `fxc.<name>` (then `fxc.<name>.1`, `.2`…) or the explicit `$node`/`node_path` path — and because the controller instance is **grafted** with the kernel's `.as()`, everything composes: `$$("fxc.badge.hero.label").set("v2")` updates the DOM *and* the instance field; user code inside the component reads `this.label`; `$$("fxc.badge.hero").someMethod()` dispatches to the class; `$computed` can drive a prop. `${prop:x|default}` tokens compile down to kernel `$${"path.x"|"default"}` interpolation with the instance path baked in, so prop reactivity IS the existing hydration engine. Slots are emulated in light DOM by default (`shadow="true"` opts into native shadow slotting); `this:`-scoped styles rewrite to the host tag and inject once per component. Lifecycle methods run inside replay boundaries — `$.ajax`/`$$("…@url").get()` in `mount()` suspends instead of blocking.

**Declarative extras** (`fxc-hydrate.js`, applied to dynamic content too):

```html
<header import="/header.html"></header>                 <!-- sync partial insert + hydrate -->
<ul import="company.clients@/clients.json"              <!-- api-load INTO the node… -->
    each="company.clients" as="client">                 <!-- …and render it, keyed + reactive -->
  <li>${client:name} — ${client:role}</li>
</ul>
```

### Declarative state → DOM

```js
$("#spinner").showWhen("app.loading", { duration: 150 });      // or hideWhen
$("#save").enableWhen("app.form.name", (v) => v?.length > 2);
$("#badge").classWhen("hot", "app.count", (v) => v > 10);
$("#search").pipe("input", "app.query", { debounce: 200, map: (v) => v.trim() });
$("#panel").bind("app.state", (v, h) => h.toggleClass("open", v.open).css("--x", v.x));
```

Every one of these accepts a node proxy **or** a dotted path string.

### `$persist` — one-line durable state (localStorage is sync — perfect fit)

```js
$persist("app.settings");                       // loads now, auto-saves every mutation beneath
$persist("app.session", { session: true });     // sessionStorage
```

Rides `fx.onStructure`, so child writes like `$$("app.settings.theme").set("dark")` are caught — no polling, no explicit save calls.

### `$history` — undo/redo over any subtree

```js
$history.track("app.todos", { limit: 50 });
$history.undo("app.todos");   $history.redo("app.todos");
$history.canUndo();           // for enabling toolbar buttons
```

Snapshots are debounced and deduplicated; applying a snapshot re-grafts through `node.set`, so the DOM follows automatically.

### Binding hygiene

All plus-layer binds are tracked per element (`FxBindings`): `.remove()`, `.empty()`, `.replaceWith()`, `.html(v)` and list re-renders dispose the affected subtree's watchers. `.unbind()`/`.unbind(true)` for manual cleanup. This fixes the silent watcher-leak pattern of raw fx-mini binds (the plus `.text(node)`/`.css(prop, node)`/`.attr(name, node)` overrides are tracked too).

## 4. Design notes

**Decoration, not forking.** fx-mini builds handles as per-call object literals, so the layer wraps `$` and decorates every result: registered extensions attach, and traversal results (`find`, `children`, `parent`, `closest`, `next`, `prev`, `each`) decorate recursively — chains never lose methods. Original methods stay callable (`prev` is passed to overrides).

**Registration registry.** `FxPlus.handle(name, fn, groupMode)` with `groupMode: "chain" | "first" | "collect"` (or a per-call function) derives group behavior automatically; explicit `FxPlus.group(name, fn)` where index-aware logic matters; `FxPlus.root(name, fn)` for `$(document)`/`$(window)`.

**Sync discipline.** Effects return immediately (the browser animates off-thread; callbacks fire on finish). AJAX keeps the sync *contract* through suspend/replay (`fx/plus/replay.js`) — background fetch + `FXSuspend` inside replay boundaries, blocking XHR only as the out-of-boundary fallback. Persistence uses synchronous storage. Nothing in the public API returns a promise.

**Error policy.** Every extension body is wrapped: failures log through the single `FxLogger` (`localStorage.setItem("fx:log", "debug")` to turn up verbosity, `$fxp.log.dump()` for the ring buffer) and chains stay alive — jQuery's forgiving temperament, but observable.

**Perf note.** Decoration adds ~80 property defines per `$()` result. Negligible for app-scale usage; if it ever matters, the registry can be compiled onto shared prototypes without changing the public API (roadmap).

## 5. Verified behavior

`node tests/run.mjs` serves the folder, drives `tests/test-plus.html` in headless Chromium, and asserts the lot: parity methods, namespace events, box-model math, queued effects + stop-freeze + scrollTop tween, ajax (200/404/into-node), **FXSuspend integration** (a request inside a click handler returns to the event loop before the response arrives and replays to completion; a suspended POST hits the server exactly once; `suspend:false` and top-level calls stay blocking), **replay transactions** (a graph `counter++` and a `$list.push` before a suspending request land exactly once — including across MULTIPLE suspends in one handler — and code placed AFTER the request runs exactly once with no ceremony), **node-first HTTP** (`$$("node@url").get()` suspends, returns the body, fills the node; `.post(payload)` fires exactly once; response templates — envelope, pick mappings, `$.ajaxSetup`-registered customs with restore; GET payload → query string; module/text `@`-loads still reach the kernel), computed, keyed list diffing (reuse/reorder/remove identity checks), bindForm two-way with radios/checkboxes/multi-selects, persist across nodes, undo/redo, watcher-disposal on `.remove()`, `$.fn` bridge, **snippet contexts** (`$(sel, htmlString)` stamps independent clones; nested selects; live handle/selector contexts don't clone; api-binding contexts; `.load()` suspending inside a handler passes through cleanly), **fxc components** (declaration → stamp with `$attr` props, named/default slots, `this:`-scoped styles verified via computed style, `$node` paths, two-way prop sub-nodes + grafted method dispatch, mount/unmount/propChange lifecycle, `import=`/`each`/`as` declarative extras), and fx-mini regression checks (reactive text bind, `@`-module load, two-way `$(sel, node)`). **74/74.**

## 6. Roadmap — worth doing next

1. **Fold into the build** as `fx::plus-*` regions so `fxm mini` ships one file again.
2. **Kernel fix candidates:** pass the resolved value to watcher callbacks (keeping the bag as a second arg); make group getters return first-element values natively; fix `transformModuleExports` mis-parsing anonymous default exports (`export default class extends X {}` captures `extends` as the class name — breaks `@`-loaded modules too; the fxc compiler carries a local workaround).
3. **TypeScript surface:** a hand-written `fx-mini-plus.d.ts` so editors autocomplete the whole `$` API.
4. **Live selectors:** a `$live(".item", handler)` built on `MutationObserver` for future-element styling/wiring (delegated events already cover behavior).
5. **Deliberately skipped for scope:** `.contents()` (text nodes), `wrapAll`, `.queue()` custom queues, `$.Deferred` (anti-goal in a sync framework), JSONP.
6. **Binding inspector:** `$fxp.inspect(el)` returning live bindings/watcher counts — cheap now that `FxBindings` exists.
7. **Server round-trip:** `$.get` into a node + `$persist` already gives offline-ish forms; a tiny `$sync("app.doc", "/api/doc")` (PUT-on-mutate, debounced) would complete the story.
8. **Wider suspend coverage:** `.pipe`/`.bind` updaters and `bindEach` renderers are not replay boundaries yet (kept narrow deliberately); wrapping them is one line each in their modules once the pattern proves out in app code.
